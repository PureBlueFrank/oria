# Oria V0.2 RAG 威胁模型

- 版本：V0.2
- 更新日期：2026-08-30
- 适用范围：Provider/RAG 完整化、文档读 ACL、混合检索、rerank 与 RAG Eval
- 当前证据：T01–T06 已通过；RAG v1 已人工批准并冻结，baseline/gates、PR/Nightly 预检、锁定 BGE/cross-encoder 对照、真实 Provider Nightly 12/12 与 DeepSeek Responses 完整 Live 卡均已完成

## 1. 安全目标与信任边界

V0.2 在 V0.1 只读边界上增加以下目标：检索前后都强制 tenant/document ACL；更新、删除和重建不会返回过期版本；RAG 文档只能作为不受信数据，不能改变 Tool 或主体权限；评测标签、holdout 和 baseline 不进入可检索语料；真实模型评测在任何请求前完成 target、凭证、数据、价格和五项预算预检。

信任边界如下：

| 边界 | 不受信输入 | 强制控制 |
| --- | --- | --- |
| 调用方 → PolicyEngine | query filter、文档 ID、正文自报 tenant/role | 受信 Context 生成不可覆盖的 ACLFilter，默认拒绝 |
| Catalog/ObjectStore → Chroma/BM25 | chunk metadata、向量投影、旧版本 | catalog + content hash 为真相源，召回后复核 active version |
| 文档/Tool → LLM | 提示词注入、伪指令、敏感字段 | `trust_level=untrusted_data`、最小披露、Tool allowlist 与 PolicyEngine 不受文本影响 |
| Eval 标签 → 检索运行时 | expected category、case ID、holdout 标注 | 标签仅由 evaluator 读取，索引只摄取版本化合成源文档 |
| Nightly 配置 → Provider | 未知 target、缺 Key、过期价格、非正预算 | 请求前 fail closed，blocked 卡固定 `request_count=0` |

## 2. 威胁与缓解

| ID | 威胁 | 当前缓解 | 剩余风险 / 门禁 |
| --- | --- | --- | --- |
| V02-TM-01 | 调用方移除 tenant/ACL filter 进行跨租户召回 | PolicyDecision 生成不可变 ACLFilter；dense/BM25 在召回前过滤并在 catalog/source 回查时再次校验 | 正式数据库 RLS 留 V0.6 |
| V02-TM-02 | 旧文档版本、残留向量或删除失败继续被引用 | active version、content hash、chunk metadata 三重校验；更新/删除遍历全部 Oria projection；重建仅使用 active catalog | 外部向量后端需独立 Adapter 卡 |
| V02-TM-03 | 恶意文档声称可提升权限或调用写 Tool | 检索结果固定标记不受信；PolicyEngine/Registry 不读取文档中的权限声明；当前仍只有只读 Tool | V0.3 引入写 Tool 时需叠加审批、幂等与输入 Guardrail |
| V02-TM-04 | restricted 文档或黑白名单原文泄漏到模型/报告 | ACL pre/post filter、规则公开投影和引用回源均执行最小披露；报告只保存 ID、类别、指标与哈希 | 真实客户语料尚未接入，不得外推为生产 DLP 已完成 |
| V02-TM-05 | expected label、Golden rationale 或 holdout 被摄取，造成数据污染 | RAG v1 标签只存在于 eval JSONL；运行时只摄取 `demo-campaign-rules@1.0.0`；manifest 记录合成来源、哈希与 split | 已批准 holdout 的任何内容/标注变更必须升 dataset version 并重新审阅 |
| V02-TM-06 | 开发者查看 holdout 结果后调参 | harness 可显式选择 development；holdout 已在人工批准后冻结；正式对照完成后未根据结果修改数据或检索实现 | 后续调优只能使用 development，新 holdout 必须升版 |
| V02-TM-07 | 用 Fixture reranker 结果冒充真实质量提升 | 报告区分 fixture/community，记录精确 embedding/reranker profile 和 eval fingerprint；真实 BGE/cross-encoder 已在固定 revision 上离线复跑 | 当前 C 级结果仅适用于六类合成规则检索，不外推为生产语料质量 |
| V02-TM-08 | 修改 baseline/gate 掩盖回归 | 数据 manifest/hash、独立 baseline/gate、critical/引用强门禁；首次 baseline 晚于人工审阅；PR `eval-golden` 禁外网复跑三管线 | baseline/gate 更新的平台 label/CODEOWNER 强制仍需仓库规则配置 |
| V02-TM-09 | Nightly 因缺预算或价格漂移产生失控费用 | 五项预算必须为正；价格快照含官方来源、核验时间和有效期；请求前按最坏 token/cost 预留，响应后按 usage 结算 | T06 真实 12/12 已验证；价格到期必须重新核验 |
| V02-TM-10 | 不完整样本仍被标记 passed | 预算账本只有结算案例数等于 expected cases 才返回 complete；超限在下一请求前终止 | T06 完整样本通过；失败/不完整路径保持 failed/blocked |
| V02-TM-11 | cross-encoder 下载远程代码或漂移版本 | model 与 40 位 revision 固定，`trust_remote_code=false`，非法/非有限 score fail closed | 首次模型下载依赖 Hugging Face 可用性和供应链；V0.8 再补 SBOM/签名 |
| V02-TM-12 | 查询或 chunk 标签声称源文档未配置的规则，产生虚假命中 | 人工审阅要求所有概念在固定源文档中存在；benefit 标签只在当前 tier 配置 `discount_rate` 时加入“折扣率” | 新规则类型或自定义 chunker 仍需独立标签一致性测试 |
| V02-TM-13 | Provider 默认推理模式与显式工具选择不兼容，导致真实工具链路失败 | DeepSeek Responses 显式 `tool_choice` 请求级关闭思考模式；契约测试覆盖 payload，真实双输入诊断及文本/流式/工具/401 Live 卡通过 | Provider 模型或兼容规则变化后必须重跑独立 Live 卡，不以 Fixture 结果替代 |

## 3. 数据与证据状态

- RAG v1 当前为 60 条全合成查询：42 development、18 holdout，六类规则各 10 条；12 条 critical 按 development/holdout 各 6 条分布，任一 split 无 critical 时评测拒绝计算。
- 当前 manifest 为 `approved`，holdout 已冻结，Fixture baseline/gates 已创建并接入 PR gate。
- 锁定 BGE/cross-encoder 已完成 C 级固定 run；指标为该合成数据集上的原始观测值，未经重复采样与人工校准，不作 release 质量阈值。
- Nightly 价格快照取自 DeepSeek 官方价格页，并按 peak 费率作保守预算；快照过期后请求前阻断。
- T06 真实 DeepSeek Nightly 12/12 和完整 Provider Live 已通过；证据只保存 request ID、model、usage、检查状态和脱敏诊断结论。

## 4. 更新触发条件

数据集获批或升版、baseline/gate 变更、真实 BGE/reranker 对照、Provider Live 请求、接入真实文档或新向量后端时，必须更新本文及对应验证卡。V0.3 新增写 Tool 后，应把文档注入威胁与审批/副作用账本一起复核。
