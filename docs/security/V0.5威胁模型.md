# Oria V0.5 威胁模型

- 版本：V0.5
- 更新日期：2026-09-10
- 适用范围：跨会话 Memory、多智能体 supervisor/Subagent、Guardrail、ABAC 与动态最小权限
- 当前证据：V0.5-T02–T04 的 Fixture/Community/Security 实现与测试；T06 对 S2–S4 执行收口

## 1. 安全目标与信任边界

V0.5 保证长期记忆只在明确 opt-in 后写入，并按 tenant + subject 隔离、可查看、导出、到期和删除；检索内容始终是非权威的不受信数据。Supervisor 与 Subagent 不得替换调用方身份或放大权限，handoff 及循环必须有严格 schema 和硬上限。模型可见工具与实际执行均由同一 PolicyEngine 决定；Prompt、RAG、Memory 和 Tool 输出中的文本不能成为授权依据。

| 边界 | 不受信输入 / 状态 | 强制控制 |
| --- | --- | --- |
| 用户/模型 → 长期 Memory | 自动摘要、伪造 opt-in、敏感或低置信内容 | `PersistentMemory.save` 强制 opt-in、namespace、TTL、sensitivity 和长度；低置信项不进入检索注入 |
| Memory 存储/向量/缓存 → 上下文 | 投毒文本、过期项、删除残留、跨 namespace 记忆 | `(tenant_id, subject_id)` 强制过滤；TTL/置信过滤；删除同一事务清空正文并删除向量，同时失效进程缓存 |
| 检索 Memory/RAG → 模型/工具 | 声称“忽略规则”、伪造业务事实或角色 | `trust_level=untrusted_data`、`authority=non_authoritative`；权威事实从业务系统读取；授权不读取内容文本 |
| Supervisor → Subagent | 伪造 handoff、越界工具名、失败后无界重试 | 严格 `SupervisorHandoff`/`SubagentResult`；spec allowlist 与调用方授权集取交集；固定最大 handoff 数与显式失败回收 |
| 主体/资源属性 → PolicyEngine | 伪造 role/tenant、缺失或畸形 organization/region/labels | 可信 actor/executor 目录、context 一致性、tenant/RBAC/ABAC deny-by-default；只从受信 `AuthorizationContext` 读取资源属性 |
| Tool schema 暴露 → Tool 执行 | 过时权限、模型伪造调用、RAG 诱导越权 | 暴露前 `authorized_tool_names`；执行前 `ToolAuthorizationGuardrail` 用同一 PolicyEngine 重新鉴权 |
| Provider/Tool 输出 → 用户/报告 | PII、凭证、毒性内容或原始提示词 | `OutputSafetyGuardrail` 递归脱敏；审计仅保留必要 ID/hash 和 reason code |

## 2. 威胁与缓解

| ID | 威胁 | 当前缓解与直接证据 | 剩余风险 / 门禁 |
| --- | --- | --- | --- |
| V05-TM-01 | 未获明确同意即自动形成跨会话记忆 | `src/oria/memory/persistent.py` 的 `save`/`save_fact` 强制 `opt_in=True`；`tests/contract/test_v05_long_term_memory.py::test_opt_in_memory_survives_sessions_and_supports_export_delete` 断言非 opt-in 拒绝和新 session 召回 | 应用层须清晰呈现同意动作；真实产品 UI/法务文案不在 Community 证据内 |
| V05-TM-02 | 跨 tenant/subject 读写记忆或借低置信、高敏项自动注入 | `PersistentMemory._authorize` 及 `SQLiteMemoryRepository.list_active` 强制 namespace/TTL/置信/敏感度；`test_namespace_ttl_and_confidence_filtering` 与 `test_sensitive_memory_and_cross_tenant_resource_are_denied` | 正式数据库 RLS 与企业身份接入留 V0.6 |
| V05-TM-03 | 记忆投毒要求忽略规则、调用高风险工具或覆盖权威业务事实 | `src/oria/tools/memory_tool.py` 将检索结果标记为不受信、非权威；PolicyEngine 不读取记忆文本；`tests/security/test_v05_memory_boundaries.py::test_poisoned_memory_stays_untrusted_and_cannot_expand_tool_authority` | 确定性注入检测可能误报/漏报；安全性依赖鉴权边界，不依赖检测命中率 |
| V05-TM-04 | TTL 到期或用户删除后仍从正文、向量或缓存召回 | `PersistentMemory.delete/_invalidate` 与 `SQLiteMemoryRepository.delete` 清空正文、删向量、失效缓存；`test_delete_clears_body_vector_cache_and_writes_only_redacted_audit` 断言 search/view/export、底层向量和缓存 | 多进程分布式缓存无当前 Adapter；接入时必须增加跨实例失效卡 |
| V05-TM-05 | 删除审计泄漏正文，或声称 checkpoint/备份立即物理清零 | `SQLiteMemoryRepository._append_delete_audit` 仅写对象 ID、actor 和 `object_hash`；同一删除安全测试直接查库确认不含正文；保留/恢复边界由 `docs/security/V0.5-Memory保留与删除.md` 公开说明 | Community 无备份或对象存储 Adapter，无法证明物理副本立即清零；V0.6 接入生产持久化时必须固化 retention 和 restore-delete 运维验证 |
| V05-TM-06 | Subagent 通过 handoff 获得调用方未授权的工具 | `src/oria/agent/supervisor.py::authorized_subagent_tools` 只取 spec allowlist 与调用方 PolicyDecision 交集，并原样继承 `ctx`；`tests/security/test_v05_supervisor_boundaries.py::test_subagent_visibility_is_allowlist_intersection_and_execution_reauthorizes` | 未来新 Subagent/spec 必须通过同等交集与执行前重鉴权测试 |
| V05-TM-07 | 伪造/畸形 handoff 或子结果绕过预期路由 | 严格 Pydantic `SupervisorHandoff`/`SubagentResult` 和确定性 `SupervisorRouter`；`tests/contract/test_v05_supervisor.py::test_handoff_and_result_are_strict_json_roundtrip_values` 及 `test_router_is_deterministic_and_attribution_wins_overlap` | 确定性关键词路由覆盖有限；未匹配请求 fail closed，不自动扩展语义 |
| V05-TM-08 | Subagent 失败、waiting 或重定向导致无界循环、预算消耗或失败被吞 | `DEFAULT_MAX_HANDOFFS=2`、state 计数和显式 termination/recovery；`test_max_handoff_limit_stops_before_invoking_another_subagent` 及 `test_failed_subagent_is_recovered_and_reported_without_retry` | 未来引入 LLM planner 前必须新 ADR、等额预算与循环/恢复 SEC/REC 门禁 |
| V05-TM-09 | Prompt/RAG 注入文本改写角色或扩大模型可见工具 | `src/oria/guardrails/input.py` 只产生内容安全告警；`src/oria/permission/tools.py` 仅读 PolicyDecision；`tests/security/test_v05_abac_guardrails.py::test_cross_tenant_forged_role_and_rag_instruction_cannot_expand_tools` 断言集合不变、越权执行拒绝与审计 | 检测告警本身不是隔离机制；新工具必须声明正确 action/resource type |
| V05-TM-10 | 工具集暴露后权限撤回，但模型仍用旧集合执行 | `src/oria/guardrails/tool.py` 在 `ToolRegistry.execute` 运行工具实现前重新鉴权；`test_tool_execution_reauthorizes_after_policy_change` 断言工具 `runs == 0` | 外部 MCP/插件 Adapter 接入时仍需在 Oria 调用边界执行重鉴权 |
| V05-TM-11 | 只读运营、活动管理员、审批人看到或执行不符合职责的工具 | LocalPolicyEngine RBAC/职责分离与 `authorized_tool_names`；`test_dynamic_tool_exposure_matches_read_admin_and_approver_roles` 逐角色对比可见集、PolicyDecision 和允许/拒绝执行 | 真实 IdP 角色映射与企业职责矩阵留 V0.6/Enterprise |
| V05-TM-12 | 伪造 role/tenant 或畸形资源属性绕过 ABAC | `src/oria/permission/local.py` 按 context 主体一致性、可信目录、tenant、RBAC、ABAC 顺序 fail closed；`test_abac_is_additive_and_deny_by_default_for_scoped_resources` 与 `test_cross_tenant_forged_role_and_rag_instruction_cannot_expand_tools` | Community 为本地可信主体 fixture；生产 JWT/JWKS/OIDC 与 PostgreSQL RLS 留 V0.6 |
| V05-TM-13 | 模型/Tool 输出泄漏邮箱、手机、凭证或毒性内容 | `src/oria/guardrails/output.py` 递归处理并返回脱敏内容；`tests/security/test_v05_abac_guardrails.py::test_output_pii_and_credentials_are_redacted` | 当前为确定性模式，不等于企业 DLP；真实语料策略和误报/漏报评估留后续版本 |

## 3. 数据与证据状态

- S2 使用本地 SQLite、确定性 embedder 和合成记忆，直接检查 `memory_items`、`memory_embeddings`、进程搜索缓存与 `audit_events`；只支持 Fixture/Community/Security 声明。
- S3 的投毒文本为合成安全 fixture，断言检索标记和 PolicyDecision；未评估真实模型对各种语义变体的遵循率。
- S4 使用本地可信 Principal、PolicyEngine、ToolRegistry 和内存工具 fixture，覆盖三角色、属性变化重鉴权、跨 tenant、伪造 role、RAG 诱导与脱敏审计。
- Supervisor 证据包含严格契约、确定性路由、上限/失败回收、权限交集，以及 Mock Provider + 本地 SQLite 的 Fixture E2E；不支持多智能体质量提升声明。
- 本文不记录真实客户数据、提示词原文、凭证或 PII。Live single/multi 对照属于 V0.5-T07；企业数据库、身份、DLP 和备份运维证据不在 V0.5 Core 内。

## 4. 更新触发条件

新增 Memory 自动写入路径、改变 opt-in/TTL/删除语义、引入分布式缓存或备份恢复、新增 Subagent 或 LLM planner、调整 handoff 上限、改变 Guardrail 处理顺序、新增 Tool action/resource type、修改角色/ABAC 矩阵、执行 T07 Live 对照或接入 V0.6 企业栈时，必须更新本文及对应测试/验证卡。
