# Oria V0.1 威胁模型

- 版本：V0.1
- 更新日期：2026-08-29
- 适用范围：场景 A 只读招商活动提案、Community 离线 Demo 与对应 Core 评测
- 证据等级：Fixture/Community；不代表真实模型或企业系统验证

## 1. 安全目标与范围

V0.1 的核心安全目标是：LLM 只能在确定性硬资格筛选结果中做软排序和起草；所有引用必须能回查至可信快照；演示链路只读且不产生 Campaign、CouponBatch 或外部系统副作用；不同 tenant/run 的上下文与 checkpoint 不串扰。

下列能力不在 V0.1 已验证边界内：真实身份认证与对外 API、写 Tool、审批后副作用、企业 Adapter、未信任插件、生产级加密与密钥轮换。这些能力不得从本文的 Core 结论中推导为“已安全”。

## 2. 资产、参与者与信任边界

| 类别 | 内容 | 信任假设 |
| --- | --- | --- |
| 受保护资产 | tenant/actor/executor 身份、商家与规则快照、引用、checkpoint、评测数据与 baseline、脱敏报告 | 本地文件系统与进程运行者受信；用户输入、检索文本、LLM 输出不受信 |
| 主要参与者 | 本地 CLI 用户、Oria Runtime/Graph、PolicyEngine、ToolRegistry、Provider、SQLite/Chroma/ObjectStore | Demo 中的 actor/executor 是本地受信 Fixture 映射，不是生产认证 |
| 边界 A | CLI 输入 → Runtime Context | 输入不得自行提升 tenant、actor 或 executor 权限 |
| 边界 B | Graph/LLM → ToolRegistry | Tool 名、参数与调用次数必须经 schema、policy 和 budget 校验 |
| 边界 C | Tool → SQLite/Chroma/ObjectStore | tenant 和访问策略在调用前后均不可被模型输出覆盖 |
| 边界 D | Provider/RAG 内容 → 最终提案/报告 | 外部或生成内容只是不受信数据，不是控制指令 |

## 3. 威胁与当前缓解

| ID | 威胁 / 滥用场景 | 影响 | V0.1 缓解与证据 | 剩余风险 |
| --- | --- | --- | --- | --- |
| TM-01 | 伪造 tenant、actor 或 executor，或在 run 间串改身份 | 越权、跨租户数据泄漏 | `Runtime.new_context()` 逐次创建 Context；PolicyEngine 根据受信主体校验 Tool；tenant-qualified checkpoint key 和隔离契约测试 | Demo 是本地受信身份映射，真实认证留待后续版本 |
| TM-02 | 用户、RAG 文档或商家字段包含“忽略系统规则并执行写入”等提示词注入 | 绕过策略、触发业务副作用 | 原始用户请求只位于 user message，不插入 system prompt；Registry 只允许两个正式只读 Tool；每个调用都经 policy/schema/budget；输出再做候选子集和业务库前后完整指纹校验；Golden `sa-v1-027` 强制拦截注入 | 不得因为模型表示“已授权”而放行；引入写 Tool 前必须新增审批和幂等边界 |
| TM-03 | LLM 将黑名单、停业/非正常营业、不满足规则的商家塞入提案 | 非法招商名单、合规风险 | `EligibilityPolicy` 在 LLM 之前确定性筛选，最终 schema 再校验推荐集是候选子集；Golden `sa-v1-028`、`sa-v1-029`、`sa-v1-030` 覆盖资格边界 | 规则快照本身若错误仍可导致错误结果，需由数据治理保证上游正确性 |
| TM-04 | 伪造、过期或无法回查的引用/快照 | 不可审计的决策 | 快照带内容哈希和版本化引用；结果落盘前校验规则/商家引用均可回查 | V0.1 未接外部时钟信任与签名证据链 |
| TM-05 | 跨 tenant 读取，或返回受限字段 | 隐私与商业数据泄漏 | 查询前的 tenant/policy 限制、返回后脱敏投影，以及跨 tenant/受限字段契约测试 | V0.1 未声明生产级 ABAC/RLS 完成 |
| TM-06 | 通过 `..`、绝对路径或符号链接逃逸 ObjectStore | 读取或覆盖任意本地文件 | ObjectStore 执行容器路径规范化与 containment 检查，相关安全测试覆盖穿越与 symlink | 本地进程运行者仍拥有其 OS 权限 |
| TM-07 | 密钥、提示词原文、PII 或受限字段进入日志/报告 | 凭证或数据暴露 | 配置公开投影脱敏 SecretStr；默认 telemetry 不捕获原文；Demo 报告只保留必要 ID、摘要和校验结果 | 真实 Provider 请求与第三方保留策略需在 Live 卡单独评估 |
| TM-08 | Provider 返回非法 schema、混入 Tool 参数或在 repair 中改变意图 | 不可预测的调用或提案 | Provider 归一化为严格类型契约；Tool 与 Response 分别校验；repair 次数受限；失败响应的 request ID/model/usage 仍进入审计与预算；最终候选/证据校验不信任 Provider | 已完成真实 DeepSeek 双跑，但未覆盖其他 Provider 或长期模型漂移 |
| TM-09 | 无限 Tool/LLM 循环、超大输出或资源耗尽 | 本地拒绝服务、成本失控 | Runtime budget 限制 Tool 调用和修复次数；缺失/非法 Provider usage fail closed；`max_candidates` 同时收窄模型可见 Tool Schema并由执行端与最终提案校验 | V0.1 无进程级资源隔离、冻结价格成本换算和分布式配额 |
| TM-10 | 伪造 migration 或部分初始化成功导致错库 | 数据损坏、不一致结果 | 版本化 migration、schema/FK 校验；初始化失败完整 unwind；重复初始化契约测试 | 生产备份/恢复和在线迁移不在 V0.1 范围 |
| TM-11 | 跨 tenant 复用 checkpoint，或利用不安全反序列化 | 状态泄漏、代码执行 | checkpoint namespace 包含 tenant；跨 tenant 与深度不可变契约测试；本地 saver 限于受信数据目录 | V0.1 未声明 checkpoint 可导入不受信文件 |
| TM-12 | 篡改 Golden、baseline 或 gate 来隐藏回归 | 虚假的“验证通过” | dataset manifest/hash、30 条人工批准记录、冻结 baseline、独立 gate 配置和 no-network CI job；关键/安全/schema/引用必须 100% | 当前未提交变更的远程 CI 尚未实跑，本地工作树仍由开发者信任边界保护 |
| TM-13 | 依赖或打包资源被替换，已安装 wheel 依赖源码目录 | 供应链注入、发布不可复现 | Python/uv 版本锁定、`uv.lock`、包内资源哈希校验，并在无源码路径的全新目录验证已安装 wheel | V0.1 未提供签名制品、SBOM 或来源证明；这些不得声称已完成 |

## 4. 关键滥用流程

### 4.1 提示词注入试图触发写入

1. 不受信内容声称可以忽略系统规则、直接发布活动。
2. LLM 即使生成该意图，Registry 也不存在可用写 Tool；policy 和 schema 不会因文本声称而改变。
3. 最终结果必须通过候选子集与业务库零副作用校验；否则 run 失败，不落为可用提案。

### 4.2 模型塞入不合格商家

1. `EligibilityPolicy` 首先根据冻结规则快照生成硬资格候选集。
2. LLM 只能对候选集排序和生成理由。
3. 任何黑名单、非正常营业或其他不在候选集的 ID，都会在结果校验时被拒绝。

## 5. 更新触发条件

出现以下任一变更时必须更新本文并增加对应安全证据：新增写 Tool 或业务副作用；接入真实 Provider/企业 Adapter；引入外部认证、API、插件或 MCP；改变 tenant/policy/checkpoint 边界；更改 Golden 数据、baseline 或安全 gate；保留原始提示词、PII 或凭证类数据。
