# 飞书审批卡片真实联调

本指南配合 [API 基础指南](api-foundation.md) 使用。当前 Oria 接收方式为已验签的 HTTP 回调；没有接入飞书官方 SDK 长连接。已被 Hermes/OpenClaw 等程序使用的应用应保留原有接收方式，使用独立测试应用准备本次 HTTP 审批验证。

## 应用与本地配置

2026-10-18 经用户明确批准，已创建独立 **OriaTest** 并添加机器人能力。用户已填好独立凭证，并明确批准将权限收敛为 `im:chat:read`、`im:chat.members:read`、`im:message:send_as_bot`、`im:message:update`，其余九项默认 IM 权限已关闭。已通过临时 HTTPS 地址校验并订阅新版 `card.action.trigger`。用户已手动保存新地址、发布 0.1.0 并将机器人加入 oriaTest；已通过真实合成审批卡片发送、PATCH 激活、接收端重启后真实签名/AES 批准及终态显示。用户确认“已批准，按钮已消失”，事务与内存重放计数均核实。原 **ClawBot** 保持现状。证据见 [真实审批验证卡](../../reports/verification/v0.6/20261018-t02-real-approval/summary.md)，下列步骤用于后续复现；完整会话与 Job/Graph 尚未交付。

将新应用信息保存在独立、仅当前用户可读写的配置文件，勿覆盖原应用凭证。以下为联调资料示例，**不是** `oria api serve --config` 的服务端配置：

```json
{
  "app_id": "example-oria-test-app",
  "app_secret": "",
  "test_chat_name": "oriaTest",
  "encrypt_key": "",
  "verification_token": "",
  "callback_base_url": ""
}
```

1. 在 **OriaTest → 凭证与基础信息** 查找 App ID 和 App Secret，写入上述本地文件。
2. 在 **OriaTest → 事件与回调 → 加密策略** 查找 Encrypt Key 和 Verification Token。新应用未开启 Encrypt Key 时，由应用所有者点击该行右侧重置图标生成，或自定义编辑并保存；Verification Token 可点击星号右侧的眼睛查看后复制。分别同步至本地 `encrypt_key` 和 `verification_token`。不要在聊天、仓库、日志或截图中暴露凭证。
3. `callback_base_url` 在受限测试接收端与可用 HTTPS 地址准备完成后填写；本轮已在用户私有文件中填写临时地址。不得将本机回环地址填为公网回调地址。

## 回调与权限

测试群后来已改名为“招商oria平台测试群”。用户另行批准的群聊合成演示为独立入口，新增单项 @ 消息权限及消息事件，见[对话演示指南](feishu-conversation-demo.md)；不改变本指南的真实审批按钮验收结论。

回调须使用新版 `card.action.trigger`，选择“将回调发送至开发者服务器”，接收路径为 `/v1/ingress/feishu/events`，通过 URL challenge 后才进入按钮实测。该地址须与本地 Encrypt Key/Verification Token、应用 ID 和当前身份目录匹配。不要使用旧版回调，不要把长连接事件伪造成带有 HTTP 签名的请求。

公开测试地址只应代理上述回调路径，其余 API/文档/管理路径不得暴露；保留 HTTPS、签名、时间窗、应用校验、身份映射和持久去重。使用临时隧道或发布测试服务前，应先明确其提供方、地址、有效时间和所转发的数据并取得相应授权；本轮已取得 Cloudflare 最多 30 分钟的明确批准，仅开放该 POST 路径；非回调路径返回 404。合成加密 challenge 公网检查通过，飞书后台也已接受地址；临时入口必须在既定时限内关闭。此处的地址校验不等于真实审批按钮回调验收。首轮入口已按时关闭；用户另行明确批准重新开启后，新地址保存成功并完成真实审批验证。两轮入口现均关闭，临时身份映射及服务端凭证副本已移除。私有资料和后台仍保存最后一次临时地址，后续实测须先更新并重新校验。

消息能力只按实际发送/更新接口需要配置最小权限。该场景无需读取通讯录、文件或全群消息。新增权限、发布应用和将机器人加入测试群属于后续显式配置步骤，本次创建批准不自动包含这些动作。测试审批人也须由用户确认，并经服务端目录映射为真实平台身份；不能自动把任意群成员提升为审批人。

## 实测与退出条件

本地测试使用 Mock/Fixture 与临时 SQLite；真实飞书联调保留 Mock/Fixture 业务运行时，但使用真实飞书 HTTP、隔离的 SQLite 和合成审批。先取得对具体测试卡片和目标群的发送批准，再通过受信内部投递服务发送无按钮卡片、持久绑定、更新为批准按钮。由已确认的独立测试审批人点击，验证真实飞书请求经过签名/加密、当前身份与 Policy/SOD 检查，审批决定、审计/outbox 与 receipt/replay 原子提交，再展示无按钮的终态。

至少记录：真实投递与 PATCH 回执、用户可见性确认、真实回调验签结果、单一审批决定、重复点击/重投不增加决定或 outbox，以及服务重启后的持久绑定。证据仅保存状态、计数和必要 ID 的摘要，不保存 raw body、原始引用、令牌或个人信息。投递不确定时停止，不自动重发。

本地用例通过不等于上述实测通过。未配置、未运行或失败必须在独立验证卡如实记录。按详细路线 §1.4，T03 可基于已有代码、schema 和契约继续实施，新增真实交互验证另行留证；T02/T03 的完整验收门禁仍须分别满足。

2026-10-21 已本地补齐 JSON 2.0 带理由拒绝与逐次授权详情/分页，旧通过卡仍只覆盖原批准切片。新的有限实测内容、目标、30 分钟窗口及退出条件已整理为[待批准方案](../../reports/verification/v0.6/20261021-t02-approval-interactions/real-validation-plan.md)，尚未重新开放入口或发送卡片；不得把本地合成回调记为新增真实验证。

## 地址校验显示“不是合法 JSON”

先检查临时入口的时限与实际响应类型。2026-10-18 的一轮临时入口按时关闭后，旧域名返回 HTTP 530 / `text/html`，飞书因此显示“返回数据不是合法的 JSON 格式”，请求并未到达 Oria。此时应在取得新临时窗口批准后更新地址并重新校验，沿用现有密钥和验签配置；该提示本身不能证明 Oria 的 JSON 协议有误。诊断见 [续验记录](../../reports/verification/v0.6/20261018-t02-real-approval/summary.md)。

## 真实按钮返回 401：时间文本兼容

本次真实签名与解密均正确，但请求头时间戳为 Go `Time.String()` 文本而非数字 Unix 秒，旧解析器返回 401。修复只支持明确格式，按数字时区偏移解析墙上时间，保留完整原文验签、未知格式拒绝与原有至多 300 秒窗口；不调整系统时间，也不关闭时效校验。单调时钟后缀用于签名绑定，不用于跨进程时间比较。完整失败记录、合成回归和真实复验均保存在上述验证卡。
