# ADR-028：确定性资格过滤与 LLM 软排序分离

- 状态：已接受
- 日期：2026-08-27
- 关联任务：V0.1-T05、V0.3-T01、V0.3-T05

## 背景

场景 A 同时包含类目、城市、黑白名单、销售组织、商品价格、商品类目等硬约束，以及语义匹配、推荐理由等软条件。若让 LLM 直接判定硬资格，结果不可重现，也无法稳定审计黑白名单和价格边界。

## 决策

1. `EligibilityPolicy` 基于已冻结的 `CampaignRuleSnapshot` 和受信商家事实执行商家硬过滤。
2. `ProductEligibilityPolicy` 基于同一规则快照的 `product_circle_policy_ref/version` 和 `ProductSnapshot` 执行商品报名硬过滤。招后选品使用独立 `assortment_policy_ref/version`，不与自动圈品规则混用。
3. 两个 Policy 都输出逐条命中/排除 reason code，对同一版本输入必须产生同一结果。
4. LLM 只能在硬过滤候选 ID 集内做软条件排序、解释和草案生成；输出越界 ID 直接被 schema/领域校验拒绝。
5. 规则缺失、冲突或不可判定时 abstain，不由 LLM 猜测缺省值。

## 后果

- 硬资格可重现、可审计并可以设置 100% 正确性门禁。
- LLM 上下文只需要脱敏候选和软条件，降低敏感范围暴露。
- 代价是需要维护规则 schema、商家/商品快照和确定性 reason code；这些是业务正确性必需成本。

## 验证

- 同一快照重放、分页圈品和重试结果一致。
- 黑白名单、类目、城市、组织、价格、关键词边界与规则冲突有 UT/CT。
- LLM 返回非候选 ID 或修改硬资格时必须失败，不得进入写节点。
