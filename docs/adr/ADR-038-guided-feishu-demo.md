# ADR-038：显式合成飞书对话演示

日期：2026-10-18。状态：已实施并验证；用户已确认真实飞书通道、Mock 模型/业务及演示角色范围。

## 背景

用户希望在改名后的测试群录制 Oria 核心流程，让开发者直观看到现有能力。场景 A 本地完整 Workflow、场景 B 有界归因和真实飞书审批回调分别已有验证，但默认消息→Job→Graph 尚未接通，V0.6-T02 未整体关闭，不能为视频宣称 T03–T05 已交付。

## 决定

增加显式 `oria feishu-demo`，与默认 API/生产身份目录分开。真实签名/AES 入站只允许单个已发现的群和操作者；所有业务使用新隔离目录、干净配置、固定 Mock/Fixture，不继承环境中的 Live 模型或企业 Adapter。群内清楚标注“演示角色”；合成审批、确认及 Mock 外部事件由既有 `local_executor` 调用，不复制业务状态机或另建 Agent。归因复用 `run_attribution_ask` 已审阅开发集 Mock 回放。

只保留白名单指令与规范化合成槽位，不保存原始群消息。参数确认前不启动活动；客户端不能指定 tenant、role、审批对象或 Graph 游标。原有 Policy、职责分离、输入边界、HITL、检查点和业务幂等继续执行。

演示指令有独立的小型本地回执文件，用于源消息/nonce 去重和先入队后响应。单进程锁、30 分钟时限和 80 条独立消息预算限制范围。未知执行/发送结果暂停后续写动作，绝不自动重发；这不替代 Durable Job、lease/fencing 或 T05 投递账本，也不装入默认 `api serve`。卡片按钮真实审批证据与本次文字控制合成角色的演示证据分开。

## 后果与验证

可展示当前已存在的核心能力，不提前更改 V0.6 阶段门禁。最小的 @ 消息权限、事件订阅和临时公网入口已按范围获批；真实群聊已完成 20 条指令、招商 10/10 与三种归因结果，临时入口已关闭。

用户取消视频，改用 GIF。首版因无法读取本机飞书界面且官方 Web 消息页为空，从实际投递的脱敏 ViewModel 生成带“格式化回放”标注的独立页面。随后用户提供 17 张真实群聊截图，当前 README 已换为原生截图裁切导览：24 个截图画面加流程与能力说明，共 29 幕。保留真实消息像素、来源序号与 Mock 范围，工程能力说明单独标识；仅去除个人头像/昵称和无关操作栏。交互页可暂停、跳转和放大，旧重排版保留为 record-replay 历史素材。检查见[真实截图素材验证卡](../../reports/verification/v0.6/20261018-feishu-native-gif/summary.md)。

测试覆盖真实本地 Graph 双审批/双等待/逐级确认/终态、检查点恢复、归因三种结论、签名加密受理、源/nonce 冲突、范围与撤权、单进程生命周期及未知结果暂停；真实飞书入站与回放素材另行留证。操作与素材说明见[演示指南](../guides/feishu-conversation-demo.md)。
