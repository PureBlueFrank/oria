# ADR-032：归因提交增加显式因果审计

- 状态：待 review（修复开发验证中，非冻结 Live 通过）
- 日期：2026-09-06
- 关联：V0.4-T05、ADR-031

## 已复现的问题

逐值引用校验只证明数值来自工具，不能证明结论的因果关系成立。原契约允许多个仍有证据支持的假设与单一确定结论同时出现，也未表达独立异常环节和共同机制证据。模型可以在 uncertainty 承认缺少连接机制，却在 conclusion 宣称共同根因，仍通过运行校验。

## 修复

新生成提交必须包含 causal_assessment：独立异常的相邻转化环节、是否观察到共同机制、机制引用。先呈现审计字段，再形成 outcome。多个异常环节且没有共同机制证据时禁止 attributed；不能通过删除仍成立的解释满足单因输出。attributed 只保留一个有证据支持的解释。

机制引用必须出现在普通 evidence 中，受同一成功调用、路径与原值校验。未观察到机制时不得把活动日期、区域或活动类型标签当作机制证明。校验失败交由已有有界修复流程处理，不在本地自动改写模型结论、替换引用或伪造弃答。

历史 v1 记录仍可读取，causal_assessment 在归档值模型中允许缺省；新生成的响应 Schema 要求非空审计对象。这是开发中的契约增强，部署和新的冻结评测必须记录新 Schema 指纹，不能沿用原批质量卡。

此外，归因图允许一次整批参数纠错。所有调用先预检，未通过批次不执行、不成为证据；未知工具和权限失败仍立即拒绝。只改变归因特化，场景 A 不变。

## 验证与限制

已有单元回归覆盖跨环节无机制禁止单因、冲突保留、机制声明必须有引用，以及首次参数纠错、重复错误和混合未知工具拒绝。真实开发探针已出现 conflicting 且引用校验通过的关注案例，仍需重复验证三类与独立语义评审。

2026-09-06 增补：v4-pro 候选开发复验中，020 两次出现模型自报双环节异常却尝试合并单因 attributed，均被本契约拦截（schema_validation_failed），无错误答案流出；修复反馈现已携带被违反规则的文案（根级校验 loc 为空时反馈校验消息）。契约在真实模型上的 fail-closed 行为得到确认。

此约束不等于自动证明因果：模型仍可能漏报异常环节，或把语义无关的真实引用标成机制证据；这些不能仅由 JSON 结构和精确值校验判定。不得将约束通过直接写成质量门禁通过。
